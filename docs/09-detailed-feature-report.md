# Python Browser Agent 详细功能报告

## 1. 报告定位

本文档补充 `docs/07-product-requirements-document.md` 中的功能清单，面向课程报告和答辩展示，重点说明每个功能为什么需要、如何实现、输入输出是什么、如何处理异常、如何验收。资料检索与整理日期为 2026-05-12。

本项目的功能设计参考了真实网页智能体和多模态 GUI 智能体的公开研究与工程实践：Mind2Web 强调真实网页任务中的候选元素筛选与动作选择；WebVoyager 和 VisualWebArena 说明视觉信息对真实网页导航、布局理解和图标理解有帮助；SeeAct 指出视觉语言模型作为网页 Agent 时必须解决 grounding 与动作约束问题；Qwen2.5-VL、UI-TARS 等模型工作说明视觉定位、界面理解和结构化动作输出正在成为 GUI Agent 的关键能力。工程实现上，Chrome DevTools Protocol 用于连接真实浏览器，Playwright 用于可复现浏览器控制、截图和自动化验收。

## 2. 功能总览

系统功能分为三层：

- 基础能力层：浏览器连接、页面观测、动作执行、安全策略、轨迹日志。
- 智能规划层：规则 Planner、LLM Planner、多轮执行、失败重规划。
- 任务技能层：搜索、填表、消息回复、页面总结、结构化抽取、结果比较、界面分析、项目分析、页面查找、文档助手、GitHub 仓库理解、研究简报。

这三层共同形成 `observe -> plan -> safety check -> execute -> observe -> artifact` 的闭环。课程展示时，不只展示浏览器被自动点击，还要展示每个任务的输入、执行轨迹、最终产物和失败原因。

## 3. 基础能力层

### 3.1 浏览器连接与运行时

#### 功能目标

让系统能够操控真实浏览器，而不是只在离线 HTML 或临时测试页面中运行。该功能解决课程 Demo 中“是否真正连接用户浏览器”的问题。

#### 输入与配置

- 目标 URL。
- Chrome CDP 地址，默认 `http://127.0.0.1:9222`。
- 是否使用 headless、slow motion、linger 等运行参数。
- 最大执行步数与截图保存目录。

#### 实现流程

1. 用户先通过 `scripts/launch_chrome_cdp.py` 启动带远程调试端口的 Chrome，或手动提供 CDP 地址。
2. 系统尝试通过 CDP 连接已启动浏览器。
3. 如果连接成功，运行模式标记为 `cdp-attached`。
4. 如果连接失败，系统回退到 Playwright 临时 Chromium，保证 demo 不因环境问题完全不可用。
5. 每次执行都在结果中记录 `browserMode`、`connectionStatus` 和 final URL。

#### 异常处理

- CDP 端口不可达：回退临时浏览器，并在 warnings 中说明。
- 页面打开失败：记录错误 URL、异常信息和最后一次可用截图。
- 用户浏览器断开：停止后续动作，不关闭用户主浏览器。

#### 验收指标

- 能连接 `127.0.0.1:9222` 并操作真实 Chrome。
- trajectory 中能区分 `cdp-attached` 与临时浏览器模式。
- 连接失败时仍能通过回退模式完成本地 demo。

### 3.2 页面观测

#### 功能目标

为 Planner 提供可 grounding 的页面状态，避免模型只根据自然语言猜测下一步动作。

#### 观测内容

- 页面元信息：URL、标题、viewport、截图路径。
- 文本结构：可见文本、headings、段落摘要。
- 交互元素：links、buttons、inputs、textareas、selects、cards、tables。
- 结构化线索：email、price、result card、table row。
- 元素字段：`id`、`selector`、`role`、`type`、`name`、`label`、`text`、`placeholder`、`href`、`value`、`formId`、`sectionLabel`、`visible`、`enabled`、`bbox`。

#### 实现流程

1. 在每一步动作前调用 Observer 读取当前页面。
2. 使用 DOM 与可见性规则筛选候选元素。
3. 按表单区域、section、文本标签和坐标位置为元素补充上下文。
4. 保存截图和简化 observation summary。
5. 将 observation 传给 Planner，并写入轨迹。

#### 设计依据

真实网页 HTML 很长且噪声多，Mind2Web 等工作表明候选元素筛选是网页 Agent 的关键步骤。仅依赖截图会缺少稳定元素句柄，仅依赖 DOM 又容易错过视觉布局和图标含义，因此本项目采用“DOM 结构 + 可见文本 + 截图路径 + bbox”的混合状态。

#### 验收指标

- 搜索框、按钮、链接、输入框能被稳定识别。
- 表单字段能区分不同 section，避免跨表单误填。
- 每步 trajectory 中保留 observation summary 和 screenshot path。

### 3.3 Planner 系统

#### 功能目标

将用户自然语言任务转化为可执行动作计划，并在 LLM 不稳定时保留规则 Planner 兜底。

#### Planner 类型

- 规则 Planner：处理搜索、填表、查找、抽取等高频确定性任务。
- LLM Planner：根据 observation 生成更灵活的动作计划。
- 校验层：对 Planner 输出做 schema 校验、动作白名单检查和安全过滤。

#### 支持动作

- 页面动作：`click`、`type`、`press`、`scroll`、`navigate`、`wait`。
- 结果动作：`extract`、`summarize`、`collect`、`compare`、`brief`、`find`、`copy`。
- 安全动作：`highlight`、`ask_user`。

#### 实现流程

1. 根据任务文本识别意图和 skill 类型。
2. 优先尝试规则 Planner，生成确定性动作或结果产物。
3. 对规则无法覆盖的任务调用 OpenAI-compatible LLM Planner。
4. 解析模型输出，要求其符合动作 schema。
5. 若解析失败或动作不安全，回退规则 Planner 或转为高亮确认。

#### 异常处理

- LLM 网络失败：使用规则 Planner 回退。
- JSON 解析失败：记录 `fallbackReason`。
- 模型输出不存在的元素：不执行，重新 observe 或请求重规划。
- 模型只给自然语言无动作：转换为 `brief` 或 `ask_user`，避免空执行。

#### 验收指标

- 每个动作都有 `reason`。
- LLM 失败不导致系统崩溃。
- 任务结束必须产生 artifact。

### 3.4 多轮执行与纠错

#### 功能目标

支持页面状态变化后的继续执行，而不是一次性生成固定脚本。该功能对应浏览器任务中的动态加载、跳转、弹窗和元素过期问题。

#### 实现流程

1. Runner 接收初始 task、URL 和 max steps。
2. 每轮执行前重新 observe。
3. Planner 基于最新页面状态生成下一步动作。
4. Executor 执行动作并返回 ok/error、output、url 和 artifact。
5. 如果动作失败，将失败原因写入下一轮输入。
6. 若达到目标或生成最终 artifact，停止任务。
7. 若达到 max steps，停止并标记未完成原因。

#### 失败类型

- 元素不存在或不可见。
- 元素不可编辑。
- 页面跳转后 selector 失效。
- 页面加载超时。
- 安全策略拦截。
- Planner 输出不合法。

#### 验收指标

- 动态页面中不会因一次旧 selector 失败直接终止。
- 轨迹中能看到失败原因和 replan 信息。
- max steps 触发时能输出阶段性结果和告警。

### 3.5 安全策略

#### 功能目标

避免 Agent 误执行具有真实后果的操作，保证课程 Demo 和真实浏览器测试的安全边界。

#### 风险分级

- 低风险：搜索、滚动、页面内查找、复制、普通导航。
- 中风险：表单填写、消息草稿、发布前编辑、下载公开文件。
- 高风险：提交、发送、删除、上传、授权、支付、下单、修改密码、验证码处理。

#### 实现流程

1. Safety 根据动作类型、元素文本、按钮 label、URL 和任务意图判断风险。
2. 低风险动作可自动执行。
3. 中风险动作默认填写草稿或高亮目标。
4. 高风险动作强制转为 `highlight` 或 `ask_user`。
5. 所有拦截记录原始动作、原因和替代动作。

#### 验收指标

- 不自动点击支付、删除、上传、授权、验证码等按钮。
- 默认不自动发送消息和提交表单。
- 用户显式允许普通 submit 时，仍保留高风险强制确认。

### 3.6 轨迹与日志

#### 功能目标

让每次任务都可复盘、可验收、可写进课程报告。

#### 日志内容

- 任务配置：task、url、model、max steps、browser mode。
- 每轮 observation summary。
- Planner 输出和来源。
- Safety 判断和 warnings。
- Executor 执行结果。
- artifact、截图路径和 final URL。

#### 报告价值

轨迹日志可直接支撑课程报告中的成功案例、失败案例、消融对比、错误归因和截图展示。相比只展示最终页面，轨迹能说明系统是真的完成了多轮感知和动作闭环。

#### 验收指标

- 每次运行都能导出 JSON。
- JSON 足以重建任务过程。
- artifact 非空率作为核心课程指标之一。

## 4. 任务技能层

### 4.1 辅助搜索

#### 功能目标

根据用户给定主题完成页面内搜索或搜索引擎查询，并输出结果摘要。

#### 典型输入

- `搜索 多模态大模型`
- `帮我找 WebVoyager 相关资料`
- `在当前页面查找安装方法`

#### 实现流程

1. 判断当前页面是否存在搜索框。
2. 若存在，匹配最可能的搜索输入框并输入关键词。
3. 若不存在，跳转搜索引擎或执行页面查找。
4. 提交搜索后重新 observe。
5. 从结果卡片、标题、链接和摘要中提取信息。
6. 输出包含关键词、来源、标题和摘要的 artifact。

#### 异常处理

- 搜索框不可见：滚动或跳转搜索引擎。
- 搜索结果为空：提示用户换关键词，并保留查询 URL。
- 页面有多个搜索框：优先主内容区搜索框，避免导航栏误匹配。

#### 验收指标

- 搜索关键词被正确输入。
- 至少提取 1 条相关结果或给出空结果原因。
- artifact 包含来源 URL。

### 4.2 表单填写

#### 功能目标

把用户指令中的字段和值填入网页表单，但不自动提交。

#### 典型输入

- `填写 姓名=张三 邮箱=zhangsan@example.com 主题=多模态智能体 备注=这是课程 Demo`

#### 实现流程

1. 从任务文本中解析 `字段=值` 对。
2. 读取 input、textarea、select 的 label、placeholder、name 和 section。
3. 进行字段匹配，优先同一 form 或 section 内的候选。
4. 执行 `type` 动作填入草稿。
5. 高亮提交按钮但不点击。
6. 输出已填写字段、未匹配字段和安全提示。

#### 异常处理

- 字段缺失：列出未匹配字段。
- 多个相似字段：选择最高置信度候选，并在 artifact 中说明。
- 表单不可编辑：停止并提示原因。

#### 验收指标

- 字段填写位置正确。
- 提交按钮不被自动点击。
- artifact 说明填写结果。

### 4.3 消息回复

#### 功能目标

在聊天、评论或邮件回复页面中填入回复草稿，并让用户确认发送。

#### 典型输入

- `回复小明：我今晚八点前把材料发你`
- `在评论框里写：这个项目结构清晰`

#### 实现流程

1. 解析回复对象和回复内容。
2. 查找 textarea、contenteditable、chat input 或 comment box。
3. 输入回复草稿。
4. 查找发送或提交按钮。
5. 高亮发送按钮并输出提示，不自动发送。

#### 安全设计

消息发送具有真实社交后果，因此默认只做草稿。即使用户指令包含“发送”，也应要求显式确认，除非当前运行模式开启了低风险显式提交且按钮不属于高风险列表。

#### 验收指标

- 回复内容完整出现在输入区域。
- 发送按钮只高亮不点击。
- trajectory 中记录安全拦截原因。

### 4.4 页面总结

#### 功能目标

将当前页面核心内容压缩为可复制摘要，适合课程资料、文档页、博客页和搜索结果页。

#### 实现流程

1. 抽取标题、headings、正文段落和卡片内容。
2. 过滤导航、页脚、按钮文本和重复文本。
3. 按页面结构生成 3 到 6 条要点。
4. 输出摘要 artifact。

#### 异常处理

- 页面文本过短：说明无法总结，并给出已看到的标题/URL。
- 页面文本过长：按 heading 分块摘要。
- 页面主要是图片：提示需要 VLM 或 OCR 支持。

#### 验收指标

- 摘要覆盖页面主题、关键模块和下一步可用信息。
- artifact 可直接复制到课程报告或实验记录。

### 4.5 结构化抽取

#### 功能目标

从页面中抽取链接、邮箱、价格、表格或结果卡片，生成结构化 JSON。

#### 支持对象

- 链接：title、href、section。
- 邮箱：address、surrounding text。
- 价格：amount、currency、item name。
- 表格：headers、rows。
- 结果卡片：title、summary、url、metadata。

#### 实现流程

1. 根据用户指令判断抽取类型。
2. 优先使用 DOM 结构抽取，减少纯文本误识别。
3. 对结果去重、排序和裁剪。
4. 输出 JSON artifact，并保留来源 URL。

#### 验收指标

- 至少支持链接、邮箱、价格、表格和结果卡片中的多类对象。
- 输出字段稳定，便于后续比较和复制。

### 4.6 结果比较

#### 功能目标

对页面中的多个候选项进行可解释比较，辅助用户选择。

#### 典型输入

- `比较这些搜索结果`
- `哪个项目更适合作为课程 demo 基座`
- `对比这些商品`

#### 实现流程

1. 抽取页面中的候选卡片或列表项。
2. 识别标题、摘要、价格、评分、时间、标签等字段。
3. 根据任务目标选择排序依据，例如相关性、价格、活跃度、可复用性。
4. 输出对比表和推荐结论。

#### 异常处理

- 候选项不足 2 个：降级为页面总结。
- 字段不完整：标记缺失，不强行排序。
- 指标冲突：明确说明推荐偏好。

#### 验收指标

- 至少比较两个候选项。
- 推荐理由能追溯到页面证据。

### 4.7 界面分析

#### 功能目标

分析一个陌生网页“能做什么”，用于展示 Agent 对页面结构和交互能力的理解。

#### 实现流程

1. 统计页面中的输入框、按钮、链接、表格和卡片。
2. 根据元素文本和布局推断页面工作流。
3. 标记搜索、筛选、下载、登录、提交、删除等关键操作。
4. 输出界面能力简报和风险提示。

#### 报告价值

该功能适合课程答辩现场演示，因为它不依赖具体网站账号，也能体现页面观测、结构理解和安全识别能力。

#### 验收指标

- 输出可交互元素统计。
- 至少识别一个主要工作流。
- 明确标出潜在风险按钮。

### 4.8 项目分析

#### 功能目标

分析项目页、论文项目主页或 GitHub 页面，判断是否适合作为课程项目参考或工程基座。

#### 实现流程

1. 提取页面标题、README 结构、模块名和资源链接。
2. 识别代码、论文、demo、文档、license、issue 等资源。
3. 判断项目成熟度、复用价值和风险。
4. 输出工程复用建议。

#### 输出字段

- 项目用途。
- 关键模块。
- 可复用部分。
- 依赖和运行线索。
- 风险与限制。
- 下一步建议。

#### 验收指标

- 能提取至少 3 类关键资源。
- 能给出可复用性结论，而不是只复述页面文本。

### 4.9 页面查找

#### 功能目标

在当前页面内定位关键词相关文本或元素，适合长文档、README、课程页面和搜索结果页。

#### 实现流程

1. 解析查找关键词。
2. 在可见文本、链接文本、heading 和元素属性中匹配。
3. 返回相关片段和所在元素。
4. 如果有可操作目标，高亮第一个候选。

#### 异常处理

- 当前视口未找到：滚动继续查找。
- 页面文本不可见：提示需要打开目标页面或等待加载。
- 多个匹配：按 heading/section 分组。

#### 验收指标

- 返回匹配片段和来源位置。
- 对可点击结果能给出高亮或下一步建议。

### 4.10 文档助手

#### 功能目标

面向技术文档页面提取安装、配置、API 使用、参数说明和示例命令。

#### 实现流程

1. 判断页面是否为文档型结构。
2. 根据关键词查找相关 heading 和代码块。
3. 提取命令、参数、配置项和注意事项。
4. 生成简短文档简报。

#### 输出字段

- 相关章节。
- 安装或配置步骤。
- API 名称与参数。
- 示例命令。
- 来源链接。

#### 验收指标

- 输出能帮助用户少读长文档。
- 保留来源 URL，便于报告引用。

### 4.11 GitHub 仓库理解

#### 功能目标

对 GitHub 仓库页进行工程化分析，补充普通页面总结无法覆盖的代码项目判断。

#### 实现流程

1. 提取仓库名称、简介、README 标题和文件结构。
2. 识别安装命令、运行命令、依赖文件和许可证。
3. 提取 stars、issues、最近更新时间等维护线索。
4. 输出项目用途、运行方式、复用风险和改造建议。

#### 异常处理

- README 缺失：根据文件结构和描述降级分析。
- 页面未登录或资源受限：记录不可见原因。
- 仓库过大：优先 README 和根目录文件。

#### 验收指标

- 能提取安装/运行线索。
- 能指出至少一个工程风险。
- 输出适合放入项目调研章节。

### 4.12 研究简报

#### 功能目标

将搜索结果页、资料页或博客列表整理为研究型输出，服务课程报告中的背景调研。

#### 实现流程

1. 收集搜索结果或资料列表。
2. 按主题、来源、时间和相关性归类。
3. 摘要每条结果的核心信息。
4. 生成“结论 + 证据 + 来源”的简报。

#### 输出字段

- 研究问题。
- 主要结论。
- 证据列表。
- 来源链接。
- 后续可读材料。

#### 验收指标

- 不只列链接，还要给出主题归纳。
- 至少保留 3 条来源信息。
- 结论和证据对应清楚。

## 5. Web UI 与 CLI

### 5.1 本地 Web UI

#### 功能目标

提供课程展示入口，让用户无需命令行即可配置 URL、任务、模型、CDP、截图目录和最大步数。

#### 展示内容

- 当前连接状态。
- 浏览器模式。
- 最终 URL。
- artifact。
- 截图列表。
- trajectory JSON。
- 导出入口。

#### 验收指标

- 一页内完成配置、执行、查看结果和导出。
- 适合答辩现场演示。

### 5.2 CLI

#### 功能目标

支持开发调试、批量评测和自动化验收。

#### 核心命令

```bash
python3 scripts/run_agent.py --url URL --task "任务"
python3 scripts/launch_chrome_cdp.py --url URL
python3 scripts/serve_agent_ui.py
python3 scripts/run_real_browser_checks.py
```

#### 验收指标

- 可复现运行单任务。
- 可批量运行真实浏览器检查。
- 输出路径稳定，便于报告收集截图和 JSON。
